# Коннектор Профи.ру (кабинет специалиста)

Читает **заказы клиентов** из кабинета специалиста на profi.ru через браузер и превращает подходящие в лиды (источник `profi`). Публичные страницы сайта показывают только специалистов (конкурентов), а заявки видны лишь после входа, поэтому коннектору нужна авторизованная сессия.

Коннектор **только читает**: не вводит логин, пароль и SMS-код, не нажимает «Откликнуться», не платит за отклик, не решает капчу и не обходит блокировку. Капча, блокировка и экран входа фиксируются в отчёте прогона как отдельная причина.

> **Правила сайта и риск аккаунта.** Автоматический доступ к кабинету может противоречить пользовательскому соглашению Профи.ру, а при подозрительной активности аккаунт могут ограничить. Используйте коннектор на свой риск, с умеренной частотой (по умолчанию — один запрос на адрес за прогон, пауза между адресами) и желательно не с основного аккаунта. Если у вас есть официальная выгрузка заказов или e-mail/Telegram-уведомления Профи.ру, они надёжнее и безопаснее.

## Как это настраивается (один раз)

Селекторы по умолчанию **пусты намеренно**: разметку кабинета нельзя угадать, а неверные селекторы дают «пусто» вместо ошибки. Пока они не заполнены, включённый коннектор не пройдёт проверку конфигурации.

### 1. Получить сессию

Вход выполняете **вы сами**, в обычном окне браузера (телефон + SMS), поэтому команда запускается на компьютере с экраном:

```bash
lead-parser profi-auth login --config config.yaml --output profi_state.json
```

Откроется окно Chromium: войдите в аккаунт **специалиста**, откройте страницу с заказами и нажмите Enter в терминале. Сохраняется только файл сессии (права `0600`), а не пароль. Загрузите его на сервер по пути `profi.storage_state` (по умолчанию `.data/profi_state.json` рядом с конфигом) и оставьте права `0600`.

Вместо файла можно подключиться к уже залогиненному браузеру: `profi.cdp_endpoint: http://127.0.0.1:9222`. Его контекст и вкладки не закрываются.

### 2. Указать страницы со списком заказов

```yaml
profi:
  enabled: true
  urls:
    - https://profi.ru/backoffice/n.php     # адрес вашего списка заказов (только https://profi.ru/...)
```

### 3. Откалибровать селекторы без передачи личных данных

```bash
lead-parser profi-auth inspect --url "https://profi.ru/…" --out profi-page-skeleton.html
```

Команда сохраняет **структуру страницы**: теги, `class`, `id`, `data-*`, но все тексты, числа, адреса и значения атрибутов заменены на форму (буквы → `x`, цифры → `9`). Имена, телефоны, суммы и ссылки в файл не попадают. Этот файл можно показать, по нему заполняются селекторы:

```yaml
profi:
  selectors:
    card: "…"        # одна карточка заказа в списке (обязательно)
    link: "…"        # ссылка на заказ внутри карточки; из пути берётся номер заказа (обязательно)
    title: "…"       # заголовок
    description: "…" # описание
    price: "…"       # бюджет
    city: "…"        # город/адрес (нужен для require_city_match)
    date: "time[datetime]"
    logged_in: "…"   # элемент, который есть на любой странице кабинета после входа (обязательно)
    empty: "…"       # надпись «заказов нет» (рекомендуется)
  order_id_pattern: '(\d{5,})'   # одна группа; применяется к пути ссылки
  require_city_match: false      # true — брать только заказы, где в city есть general.city
```

### 4. Проверить

```bash
lead-parser profi-auth status          # сессия жива? сколько карточек найдено (без вывода содержимого)
lead-parser --check-config --config config.yaml
```

## Как ведёт себя в работе

| Ситуация | Что видно в отчёте прогона |
| --- | --- |
| Всё хорошо | `ScanResult` по каждой странице, `coverage=current_listing`, число просмотренных/кандидатов |
| Нет файла сессии / сессия истекла / экран входа | `AuthRequired: …` — нужно снова выполнить `profi-auth login` |
| Капча, HTTP 403/429 | `Blocked: …` — запрос не повторяется, остальные адреса продолжаются |
| Страница изменилась, карточек нет | `NoCardsOrLayoutChanged` (если не задан `empty` и нет подтверждения «пусто») |
| Ни одну карточку разобрать не удалось | `MarkupChanged` — нужна повторная калибровка (`inspect`) |
| Карточек больше `max_orders_per_page` | `BudgetExhausted` — прочитаны только первые N |

Пустой список **без** подтверждающего селектора `empty` считается ошибкой, а не «успешно, заказов нет»: иначе смена вёрстки осталась бы незамеченной.

## Ограничения

- **Снимок страницы.** Читается одна страница списка на адрес (без прокрутки и пагинации); устойчивого курсора у списка нет. Повторные заказы отсекает уникальный ключ лида (`profi:<номер заказа>`).
- **Контакты клиента скрыты** до платного отклика — коннектор их не получает; телефон берётся только из текста заказа, если клиент сам его написал.
- **Память сервера.** Запуск Chromium на слабом сервере (менее ~1 ГБ) может не хватить памяти и мешать другим заданиям. Надёжнее держать браузер на другой машине и подключаться через `cdp_endpoint`, либо запускать сбор на машине с запасом.
- **Файл сессии = вход в аккаунт.** Хранить вне Git, права `0600`; он обновляется после здоровых прогонов (свежие cookie). Если мог утечь — завершите сессию в настройках Профи.ру.

## Устройство

| Модуль | Назначение |
| --- | --- |
| `integrations/profi/pages.py` | проверка страницы (капча/блокировка/вход), чтение карточки, анонимизатор разметки |
| `integrations/profi/browser.py` | авторизованный контекст: файл сессии или CDP; закрывается только своё; атомарная запись сессии `0600` |
| `integrations/profi/collector.py` | обход адресов, предфильтр по ключевым словам, отчёты `ScanResult`, сохранение лидов |
| `interfaces/cli/profi_auth.py` | `login`, `status`, `inspect` |
