# Заказы Профи.ру через почту

Профи.ру присылает специалисту письма о новых заказах. Коннектор читает эти письма из вашего почтового ящика по IMAP и превращает подходящие в лиды (источник `profi`). Это проще и безопаснее, чем автоматизация кабинета через браузер: нет входа на сайт, браузера, капчи и риска блокировки аккаунта Профи.ру, а Chromium на слабом сервере не нужен.

Коннектор **только читает**: ящик открывается в режиме `readonly`, письма берутся через `BODY.PEEK`. Ничего не помечается прочитанным, не перемещается и не удаляется.

## Настройка

### 1. Включить уведомления на почту
В настройках профиля специалиста на Профи.ру включите e-mail-уведомления о новых заказах (на тот адрес, который будет читать парсер).

### 2. Лучше завести отдельный ящик
Создайте отдельный почтовый ящик только для уведомлений Профи.ру и настройте на него уведомления (или пересылку). Тогда пароль приложения даёт доступ только к этим письмам, а не к вашей основной почте.

### 3. Включить IMAP и создать пароль приложения
Обычный пароль не используйте: нужен **пароль приложения**.

| Почта | IMAP-сервер | Что сделать |
| --- | --- | --- |
| Яндекс | `imap.yandex.ru` | Почта → Настройки → Почтовые программы → включить IMAP; ID.Яндекс → Пароли приложений |
| Mail.ru | `imap.mail.ru` | Настройки → Все настройки → Почтовые программы; пароль для внешнего приложения |
| Gmail | `imap.gmail.com` | Включить двухэтапную защиту → Пароли приложений |
| Другая | указан в справке провайдера | порт `993`, SSL/TLS |

### 4. Конфигурация

```yaml
profi_mail:
  enabled: true
  host: imap.yandex.ru
  port: 993                        # только IMAP поверх TLS
  username: leads@example.com
  # пароль приложения — в .env, не в Git:  PROFI_MAIL_PASSWORD=...
  folder: INBOX
  sender_domains: [profi.ru]       # принимаются письма с profi.ru и его поддоменов
  lookback_days: 3                 # окно при первом запуске
  max_messages_per_run: 200
```

### 5. Проверить

```bash
lead-parser profi-mail status      # вход, папка, сколько писем от profi.ru в окне (содержимое не печатается)
lead-parser --check-config --config config.yaml
```

Если писем нет, `status` подскажет включить уведомления на стороне Профи.ру.

## Outlook.com / Microsoft 365 (OAuth2, без пароля)

Microsoft отключила вход по паролю в IMAP: сервер отвечает «Basic authentication is disabled», принимается только OAuth2. Коннектор поддерживает его через *device code flow*: **пароль ящика не вводится и не хранится нигде**, вы один раз подтверждаете вход в браузере, а токены обновляются автоматически.

### 1. Зарегистрировать приложение (один раз, бесплатно)
1. Откройте <https://entra.microsoft.com> → **Identity → Applications → App registrations → New registration** (то же доступно в portal.azure.com). Для личной учётной записи Microsoft портал может предложить завершить бесплатную регистрацию каталога, платить за регистрацию приложения не нужно.
2. Название любое (`lead-parser`). **Supported account types:** *Accounts in any organizational directory and personal Microsoft accounts*. Redirect URI оставьте пустым.
3. **Authentication → Advanced settings → Allow public client flows = Yes** → Save.
4. **API permissions → Add a permission → APIs my organization uses → Office 365 Exchange Online → Delegated permissions → `IMAP.AccessAsUser.All`** → Add. (Согласие даётся при первом входе.)
5. На странице *Overview* скопируйте **Application (client) ID**. Это не секрет, client secret не нужен.

### 2. Конфигурация

```yaml
profi_mail:
  enabled: true
  host: outlook.office365.com        # для личных ящиков подходит и imap-mail.outlook.com
  username: you@outlook.com
  auth: oauth2
  oauth:
    client_id: 'ВАШ_APPLICATION_CLIENT_ID'   # или переменная PROFI_MAIL_OAUTH_CLIENT_ID
    tenant: consumers                         # личные ящики; для рабочего Microsoft 365 — ID каталога или organizations
```

### 3. Войти и проверить

```bash
lead-parser profi-mail login      # покажет адрес и короткий код: откройте в браузере, войдите в ящик, подтвердите
lead-parser profi-mail status     # вход, папка, число писем от profi.ru в окне
```

Токены сохраняются в `.data/profi_mail_oauth.json` (права `0600`, запись атомарная). Перед каждым запуском токен при необходимости обновляется, а новый refresh-токен записывается раньше, чем используется. Если доступ отозван или истёк, отчёт прогона скажет `AuthFailed: … run lead-parser profi-mail login`.

| Ситуация | Что видно |
| --- | --- |
| Нет входа | `NotLoggedIn: run lead-parser profi-mail login` |
| Доступ отозван / срок вышел | `invalid_grant: … run lead-parser profi-mail login` |
| Приложение не найдено / не разрешён public client | `unauthorized_client` / `invalid_client` и первая строка описания от Microsoft |
| Сервер отверг токен | `AuthFailed: the server rejected the OAuth2 token …` |

> Токены и коды в отчётах и логах не печатаются (выводится только одноразовый код входа, который нужен вам для браузера).

## Как разбирается письмо

Шаблон письма заранее неизвестен, поэтому разбор не завязан на разметку:

- **Текст лида** = тема + читаемое тело письма (HTML превращается в текст), прямые ссылки из текста убираются, размер ограничен 5000 символами.
- **Номер заказа и ссылка** = первая ссылка на `https://…profi.ru/…`, в пути которой есть номер (`order_id_pattern`, по умолчанию 5+ цифр). Ключ лида — `profi:<номер>`, повторные письма об одном заказе не дублируются.
- **Нет ссылки с номером** → лид получает стабильный ключ `mail-…` из `Message-ID` (письмо одно — лид один).
- Дальше — общий конвейер: ключевые слова, ИИ-фильтр, Sheets, Telegram.

Приветствия и подписи можно отрезать необязательными регулярными выражениями `body_start_regex` и `body_end_regex`. Чтобы подобрать их, не показывая письма никому:

```bash
lead-parser profi-mail inspect --count 1 --out skeleton.txt --raw-out raw.txt
```

`skeleton.txt` — структура письма с замаскированным содержимым (буквы → `x`, цифры → `9`), её можно показывать. `raw.txt` — читаемый текст только для вас (права `0600`), его не отправляйте.

## Безопасность

| Что | Как |
| --- | --- |
| Подмена отправителя | принимаются только `sender_domains` (точное совпадение домена или поддомена, `profi.ru.evil.com` не проходит); письмо с `dkim/spf/dmarc=fail` в `Authentication-Results` отвергается и считается в отчёте как `failed_authentication` |
| Пароль | только пароль приложения; хранится в `.env`/переменной `PROFI_MAIL_PASSWORD`; не печатается и не попадает в отчёты (в ошибках — только имя класса или фиксированный текст) |
| Шифрование | только `IMAP4_SSL` (TLS), пароль по открытому каналу не уходит |
| Изменения в ящике | нет: `readonly`, `BODY.PEEK`, ни `STORE`, ни `EXPUNGE` |

> **Данные клиентов.** Тексты заказов проходят тот же конвейер, что и остальные источники: попадают в ИИ-фильтр (OpenRouter), Google Sheets и Telegram. Убедитесь, что это допустимо для ваших условий с Профи.ру и клиентов.

## Как ведёт себя в работе

Курсор — `uidvalidity` + `last_uid`: при следующем запуске читаются только новые письма. Курсор двигается **после** сохранения лидов страницы. Если писем больше `max_messages_per_run`, отчёт покажет `BudgetExhausted` (отставание), а остальное прочитается в следующем прогоне. Смена `UIDVALIDITY` (ящик пересоздан) сбрасывает курсор на окно `lookback_days`; дубли отсекает ключ лида.

| Ситуация | Отчёт прогона |
| --- | --- |
| Неверный логин/пароль, IMAP выключен | `AuthFailed: …` (прогресс не сбрасывается) |
| Папка не найдена | `FolderNotFound` |
| Сеть/TLS/таймаут | имя исключения |
| Письмо не удалось прочитать | `Message uid=N: …`, остальные письма обрабатываются |
| Писем нет | успешный прогон без кандидатов (ящик доступен) |

## Ограничения

- Видно только то, что Профи.ру прислал в письме. Контакты клиента обычно скрыты до платного отклика и в письмо не попадают; телефон берётся из текста, только если он там есть.
- Скорость определяется доставкой писем: это не мгновенные уведомления, а проверка при каждом прогоне.
- Если Профи.ру изменит письма, разбор текста продолжит работать (он не привязан к шаблону), но могут измениться шапки/подписи — подправьте `body_start_regex` / `body_end_regex`.
