# Следующий этап: релиз заказчику и этап 2

Этот документ фиксирует будущую подготовку, а не разрешение на выкладку. Текущая работа меняет код/тесты/документацию и готовит review; рабочее расписание, клиентская таблица и получатели не изменяются.

## До первого клиентского запуска

- Изменения кода проверяются CI и могут быть слиты в main до клиентской выкладки. Администратор включает защиту main по `branch-protection.json`; release tag и клиентский запуск выполняются при подготовке релиза.
- Зафиксировать город, вид работ, источники, реальные назначения Sheets/Bot, режим ИИ, бюджет запросов и ответственного за сбои. Для VK ID использовать зарегистрированное приложение и проверить права именно нужных методов.
- Сохранить закрытые backup и выполнить dry-run миграции. Проверить распознавание старых ID и возможность восстановления, не теряя заметки/историю.
- На отдельных согласованных таблице/получателях проверить реальные доступы, телефон как текст, один повтор записи Sheets, получение уведомления и восстановление очереди. Обычные тесты этих аккаунтов не используют.
- Выполнить явную online-оценку модели на размеченном наборе целевого города, зафиксировать допустимые precision/recall и разбор неоднозначных случаев. Синтетический offline recall не является SLA качества живой модели.
- Согласовать полноту источников: VK/TG показывают отставание; глобальный VK-поиск и первая страница Avito дают ограниченную выборку. Согласовать обработку блокировки и недоступного канала.
- Подготовить версию, changelog, установку пакета из lock или проверенного wheel, systemd/cron и короткую инструкцию заказчику. Архитектура и границы расширения описаны в `architecture.md`; SQLite schema v1 и старые CLI сохранены. Критерий приёмки — зафиксированный смоук-отчёт, проверенное восстановление и подписанный перечень ограничений.

## Кандидаты для этапа 2, требующие согласования объёма

1. Разметка рабочих кандидатов человеком, обратная связь о сделках и измерение реального пропуска заявок по источникам. Не смешивать качество модели, доступность источника и коммерческий результат.
2. Наблюдение за устойчивым отставанием/ошибками, оповещения ответственному и целевые SLO.
3. Расширение Avito после проверки доступа/ограничений: пагинация, устойчивые селекторы, воспроизводимые примеры текущей вёрстки.
4. Удобная очередь review и управление остановленными заданиями/явным историческим replay с предварительным планом.
5. Несколько клиентов/городов, разграничение данных и независимые назначения. Текущий процесс/БД рассчитаны на один настроенный проект; масштабирование не обещано этой версией.
