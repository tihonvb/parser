# Telegram-аккаунт (user client, не бот)

Сборщик каналов и поиск источников работают от имени **вашего Telegram-аккаунта** через MTProto (Telethon). Всё, что касается подключения к аккаунту, собрано в одном модуле: [`telegram/client.py`](../src/lead_parser/infrastructure/integrations/telegram/client.py). Уведомления о лидах отправляет отдельный **бот** (`notifications.telegram`, см. `notifications.py`) — это другой токен и другие настройки.

## 1. Получить `api_id` и `api_hash`

1. Откройте <https://my.telegram.org> и войдите номером телефона аккаунта.
2. **API development tools** → создайте приложение (название и короткое имя любые).
3. Скопируйте **App api_id** (число) и **App api_hash** (32 символа `0-9a-f`).

Если страница отдаёт ошибку, повторите позже или с другой сети: это ограничение на стороне Telegram.

## 2. Прописать в конфигурации

Любой из способов (приоритет: переменные процесса → `.env` → `config.yaml`):

```bash
# .env рядом с config.yaml (права 0600, в Git не попадает)
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
```

или в `config.yaml`:

```yaml
telegram:
  enabled: true
  api_id: '1234567'
  api_hash: '0123456789abcdef0123456789abcdef'
  session_name: .data/telegram        # файл сессии; путь от каталога конфигурации
  channels: ['@example_channel']
```

На сервере с деплоем по тегу значения кладутся в `/var/lib/parser/.env` или `/var/lib/parser/config.yaml`, а не в репозиторий и не в GitHub Secrets (CI они не нужны).

## 3. Проверить и войти

```bash
lead-parser telegram-auth status    # настройки, файл сессии, какой аккаунт; секреты не печатаются
lead-parser telegram-auth login     # один раз, интерактивно: номер телефона, код из Telegram, пароль 2FA
```

`status` возвращает код `0`, если сессия авторизована, и `2`, если не хватает настроек, файла сессии или входа; в выводе указано, что именно исправить. Телефон показывается только маской (`+*********67`), `api_hash` не печатается.

После `login` в каталоге из `session_name` появляется файл `*.session` с правами `0600`.

## Что важно знать

- **Файл сессии — это вход в аккаунт.** Храните его вне Git, права `0600`, не копируйте и не отправляйте. Утечка = полный доступ к аккаунту. Если файл мог утечь, завершите сессию в Telegram: *Настройки → Устройства*.
- **Одна сессия — один процесс.** Не запускайте сбор, `discover` и `login` одновременно с одним и тем же файлом сессии: приложение уже защищает свой цикл блокировкой, но ручные команды в обход неё могут конфликтовать.
- **Нагрузка на аккаунт.** Telegram ограничивает частоту запросов (`FloodWait`). Клиент не ждёт и не повторяет запросы в цикле: канал помечается как прочитанный не полностью и продолжается в следующем прогоне. Массовые вступления в каналы и рассылки с обычного аккаунта Telegram может счесть спамом и ограничить аккаунт — приложение ничего не вступает и не пишет само (discovery только читает поиск).
- **Нет сессии — нет сбора.** Без авторизации сборщик не запрашивает код сам: он останавливается с `TelegramAuthorizationRequired`, а источник отмечается как неудачный в отчёте прогона.

## Как это устроено

| Часть | Назначение |
| --- | --- |
| `TelegramApiSettings.from_config` | `api_id`, `api_hash`, путь сессии; без обращения к сети; ошибки настройки с понятным текстом |
| `TelegramAccount.new_client` | единственное место, где создаётся `TelegramClient` (таймауты, `flood_sleep_threshold=0`, число повторов) |
| `TelegramAccount.session()` | `async with`: подключение с таймаутом, проверка авторизации, **всегда** отключение, права `0600` на файлы сессии |
| `TelegramAccount.login()` | интерактивный вход, вызывается только из CLI |
| `TelegramAccount.status()` | без файла сессии сеть не используется; иначе — какой аккаунт |

Сборщик (`collector.py`) и поиск источников (`discovery.py`) получают клиент из `TelegramAccount.new_client`; их собственная логика курсоров, таймаутов каналов и очистки не менялась.
