# Telegram без аккаунта: публичные каналы через веб-превью

Если получить `api_id` / `api_hash` не удаётся (на `my.telegram.org` частая ошибка при создании приложения), публичные каналы можно читать без аккаунта: у каждого открытого канала есть веб-превью `https://t.me/s/<канал>`, которое видит любой браузер.

## Включение

```yaml
telegram:
  enabled: true
  transport: public_web          # вместо account; api_id/api_hash не нужны
  channels:
    - '@durov'                   # @имя, имя, https://t.me/имя — все формы равнозначны
    - https://t.me/some_channel
  lookback_hours: 48
  public_web:
    max_pages_per_channel: 15    # ~20 сообщений на страницу, т.е. до ~300 за прогон на канал
    request_delay_seconds: 1.0   # пауза между запросами
    request_timeout_seconds: 20
```

Проверка без сети: `lead-parser --check-config --config config.yaml`. Вход в аккаунт и `telegram-auth` в этом режиме не нужны.

## Что делает и как себя ведёт

- Читает страницы от новых сообщений к старым (`?before=<id>`), останавливается на границе окна `lookback_hours` или на сохранённой точке прошлого прогона.
- Те же курсоры и отчёты, что у режима с аккаунтом: каждая страница сохраняется до продвижения точки; если бюджет страниц исчерпан, отчёт показывает **неполный сбор (отставание)**, а следующий прогон продолжает с места остановки.
- Вежливый режим: один запрос за раз, пауза между страницами и каналами, честный `User-Agent`. На HTTP 429 канал останавливается и продолжится в следующем прогоне.
- Ничего не публикуется, ни в какие каналы не вступает.

## Ограничения (в отчёте они видны, а не скрыты)

| Что | Как это проявляется |
| --- | --- |
| Только **публичные** каналы с включённым превью | Приглашения (`t.me/+…`, `joinchat`), числовые id, закрытые чаты, каналы с отключённым превью — понятная ошибка `PublicWebUnsupported` / `Unavailable` в отчёте, остальные каналы работают |
| ~20 сообщений на страницу | Очень активные каналы могут не уложиться в бюджет: будет «неполный сбор» и догон в следующих прогонах; бюджет повышается `max_pages_per_channel` (до 500) |
| Нет автора, веток ответов и медиа | У лида пустой `author`, текст берётся только из тела поста |
| Нет числового id канала | Устойчивый идентификатор источника — `telegram:web:<имя>` (имя в нижнем регистре) |
| Страница может измениться | При смене вёрстки канал отдаст `Unavailable`/пустой результат; обычные страницы разобраны стандартным парсером, поправка локальна (`public_web.py`) |

## Смена режима

`account` и `public_web` дают разные идентификаторы источников и сообщений (`telegram:<числовой id>` и `telegram:web:<имя>`). Если переключить режим на работающем экземпляре, посты за окно `lookback_hours` будут прочитаны как новые. Переключайтесь осознанно, лучше до первого боевого запуска.

## Когда нужен режим с аккаунтом

Закрытые чаты, каналы без превью, приглашения, большие объёмы с точным порядком и автор сообщений — только через `transport: account`: получение ключей и вход (документ `telegram-account.md` в ветке с коннектором аккаунта).
